# Units of Work

## Overview

This document decomposes the Supplier Onboarding, Duplicate Detection & Risk Scoring solution into buildable units for AIDLC Construction.

The selected decomposition follows the Oracle-layer strategy:

- Visual Builder UI
- ATP/ORDS foundation
- Duplicate detection and risk logic
- OIC/Fusion/Gemini integration
- Audit, testability, and demo evidence

The first new construction unit is `UOW-002 ATP/ORDS Supplier Request Foundation`.

## Selected Planning Answers

| Question | Selected Answer | Effect |
|---|---|---|
| Unit decomposition | A | Use Oracle-layer units. |
| Next unit | A | Build ATP/ORDS Supplier Request Foundation first. |
| ATP and ORDS boundary | A | Treat ATP and ORDS as one combined construction unit. |
| Fusion reference data | C | Design tables for both seeded/mock and OIC-synced Fusion reference data. |
| ATP output | A | Generate schema scripts, seed data, PL/SQL packages, ORDS definitions, and tests. |
| Code organization | A | Use Oracle-focused workspace folders. |
| Property-based testing | A | Include example-based and property-based test plans. |

## Code Organization Strategy

Application artifacts must be generated outside `aidlc-docs/`.

Recommended workspace-root structure:

| Path | Purpose |
|---|---|
| `oracle/atp/schema/` | DDL scripts for ATP tables, indexes, constraints, and views. |
| `oracle/atp/packages/` | PL/SQL package specifications and bodies. |
| `oracle/atp/seed/` | Configuration, risky countries, mock Fusion supplier reference data, and demo scenarios. |
| `oracle/ords/modules/` | ORDS module, template, handler, and privilege definitions. |
| `oracle/oic/` | OIC integration design/export placeholders and payload mapping artifacts. |
| `visual-builder/` | Visual Builder export notes, custom page code, and future service binding assets. |
| `tests/example/` | Example-based tests and scenario scripts. |
| `tests/property/` | Property-based tests and generators for business logic and transformations. |

## UOW-001: Visual Builder Prototype UI

### Purpose

Provide the three-role user experience for Requester, Reviewer, and Admin.

### Responsibilities

- Render Requester dashboard and New Request form.
- Render Reviewer dashboard, request review, duplicate/risk evidence, and ERP supplier master view.
- Render Admin dashboard, OIC/Fusion logs, retry view, and property-based test evidence view.
- Keep the visible prototype roles to `Requester`, `Reviewer`, and `Admin`.
- Later bind screens to ORDS endpoints generated by UOW-002 and later units.
- Keep Visual Builder as a presentation layer; it must not own workflow state or call Fusion directly.

### Primary Components

- C-001 Visual Builder Application
- C-013 Dashboard Query Component, through ORDS responses

### Primary Services

- S-001 Supplier Request Service
- S-006 Document Service
- S-008 Dashboard Service
- S-007 Review Service
- S-011 Integration Support Service

### Output Artifacts

- Visual Builder page/source export notes.
- UI service binding definitions when ORDS endpoints exist.
- Updated preview/demo screenshots if needed.

## UOW-002: ATP/ORDS Supplier Request Foundation

### Purpose

Create the database and REST foundation for supplier request persistence, IAM subject/role authorization context, request lifecycle state, dashboard/query data, validation/assessment result storage, integration job/log storage, and ORDS access.

This is the first backend construction unit.

### Responsibilities

- Create ATP tables for flattened supplier requests, request documents, request assessments, AI assessment history, action history, integration jobs, Fusion supplier reference data, structured configuration, lookup values, and audit evidence.
- Support both seeded/mock Fusion supplier reference records now and OIC-synced supplier reference records later.
- Create PL/SQL packages for request create/update/submit, status transitions, authorization checks, dashboard queries, review action persistence, integration job persistence, configuration, projections, and audit writes.
- Define ORDS modules, routes, handlers, and privileges for Visual Builder.
- Provide seed data for configuration, risky countries, supplier references, and demo request/log scenarios.
- Provide example-based and property-based test scaffolding where business logic or transformations are included in this unit.

### Boundary

UOW-002 owns persistence, API contracts, and workflow/data foundations. It may include simple mandatory validation needed for submit behavior, but deeper duplicate detection, risk scoring, matching thresholds, scoring weights, and payload transformations are owned by later units.

### Primary Components

- C-002 IAM Subject Authorization Context
- C-003 ORDS API Layer
- C-004 Supplier Request Repository
- C-005 Request Workflow Component
- C-006 Validation Component, storage and foundational checks
- C-007 Supplier Master Reference Component, storage and seed/sync-ready structure
- C-011 Document Component, metadata only
- C-012 Review Decision Component, persistence
- C-013 Dashboard Query Component
- C-016 Integration Log and Retry Component, persistence
- C-017 Audit Component

### Primary Services

- S-001 Supplier Request Service
- S-002 Validation Service, foundational storage/checks
- S-006 Document Service, metadata
- S-007 Review Service, persistence and workflow state
- S-008 Dashboard Service
- S-011 Integration Support Service, log and retry metadata
- S-012 Audit Service

### Expected Construction Outputs

- `oracle/atp/schema/` DDL scripts.
- `oracle/atp/packages/` PL/SQL package specs and bodies.
- `oracle/atp/seed/` configuration, risky-country, supplier reference, and demo seed data.
- `oracle/ords/modules/` ORDS endpoint definitions.
- `tests/example/` example test scenarios for request lifecycle and API contracts.
- `tests/property/` property-based test scaffolding for normalization, idempotent status operations where applicable, and data transformation invariants introduced in this unit.
- `aidlc-docs/construction/atp-ords-foundation/code/` generation summary only.

## UOW-003: Duplicate Detection and Risk Logic

### Purpose

Implement explainable duplicate matching, business validation rules beyond the foundation, and supplier risk scoring.

### Responsibilities

- Normalize supplier names, addresses, email domains, phone values, tax registration values, and masked/protected bank references.
- Detect exact tax registration matches.
- Detect exact bank reference matches where available.
- Implement lightweight fuzzy supplier name matching.
- Combine country, address, email domain, phone, tax, and bank factors into duplicate match reasons.
- Calculate Low, Medium, High, or Critical risk with explainable factors.
- Store duplicate and risk outputs through UOW-002 structures.
- Provide example-based and property-based tests for normalization, matching invariants, score bounds, and classification consistency.

### Primary Components

- C-006 Validation Component
- C-008 Duplicate Detection Component
- C-009 Risk Scoring Component
- C-018 Testability Component

### Primary Services

- S-002 Validation Service
- S-003 Duplicate Detection Service
- S-004 Risk Scoring Service

## UOW-004: OIC, Fusion, and Gemini Integration

### Purpose

Connect approved supplier requests to Fusion supplier creation, synchronize Fusion supplier master references into ATP, and generate Gemini advisory summaries.

### Responsibilities

- Define OIC supplier creation flow from approved ATP request data to Fusion payload.
- Support realistic mock Fusion responses when real Fusion access is unavailable.
- Store Fusion success/failure responses back to ATP through UOW-002 structures.
- Define OIC supplier master sync flow into ATP supplier reference tables.
- Define Gemini request/response orchestration through OIC.
- Store AI summaries and recommendations in ATP.
- Implement integration error classification and retry eligibility using stored log data.
- Provide payload transformation tests, including property-based transformation tests where applicable.

### Primary Components

- C-010 Gemini Explanation Component
- C-014 Supplier Creation Integration Component
- C-015 Supplier Master Sync Component
- C-016 Integration Log and Retry Component
- C-018 Testability Component

### Primary Services

- S-005 AI Explanation Service
- S-009 Supplier Creation Integration Service
- S-010 Supplier Master Sync Service
- S-011 Integration Support Service

## UOW-005: Audit, Testability, and Demo Evidence

### Purpose

Consolidate auditability, property-based testing evidence, seeded scenario coverage, and build/test documentation.

### Responsibilities

- Ensure reviewer decisions, AI summaries, status changes, integration attempts, and retry attempts are auditable.
- Provide seeded demo scenarios for clean, duplicate, high-risk, validation-failure, and integration-failure cases.
- Consolidate property-based test coverage for duplicate detection, risk scoring, normalization, and payload transformation.
- Ensure example-based tests remain for business-critical scenarios.
- Produce build and test instructions for all units.

### Primary Components

- C-017 Audit Component
- C-018 Testability Component

### Primary Services

- S-012 Audit Service

| Stage | Applicability |
